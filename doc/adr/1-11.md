# 外部ギャラリーサイト閲覧機能の設計

## 概要
外部の画像ギャラリーサイトに掲載されている作品を、ダウンロードせずにアプリ内で閲覧する機能を追加する。
対象サイトの情報はリポジトリにコミットせず、ローカル管理のサイトプロファイルとして分離する。

## 前提と制約

### 利用条件
- 個人利用のみを想定する
- 保存するのは作品の URL とタグ等のメタデータのみとし、画像はディスクに保存しない
- 閲覧のたびに画像をサイトから取得する
- ログインが必要な機能は扱わない（Cookie や資格情報を一切保存しない）

### 非機能要件
- **マルウェア対策**: サイトの HTML・スクリプト・広告をブラウザとして描画しない
- **公開リポジトリとの分離**: サイトを連想させる URL、タグ、HTML 構造、カテゴリ名はコミットしない

## 設計方針

### 1. 汎用エンジン + サイトプロファイルの二層構造

公開側には「外部ギャラリーサイトを閲覧する仕組み」だけを置き、サイト固有の情報はプロファイルに閉じ込める。

#### 公開側（コミットする）
- `SiteProfile` インターフェース
- 一覧・作品・ページの型定義（`ExternalWork`、`ExternalPage` など中立な命名）
- 取得パイプライン（HTML 取得、パース呼び出し、画像取得と検証）
- お気に入り / NG の永続化
- UI（一覧、作品閲覧、フィルタ）
- 架空サイト向けのサンプルプロファイル `src/shared/sites/example/`

#### プロファイル側（gitignore）
- `src/shared/sites/private/` 配下に TypeScript モジュールとして配置（main と renderer の両方から読むため `shared` に置く）
- 含める情報:
  - ベース URL、許可ホスト一覧（HTML 取得先と画像配信先）
  - 一覧 URL の組み立て（表示カテゴリ・言語の指定方法、表示モード、ページネーション）
  - **表示対象カテゴリの名称と識別子**（公開側には置かない）
  - 言語フィルタの値
  - CSS セレクタ、タグの名前空間の解釈（artist タグの判定方法）
  - 作品ページから各ページの HTML を辿り、実画像 URL を取り出すロジック
  - リクエスト間隔・同時接続数の推奨値

#### 形式の選択
宣言的 JSON ではなく TypeScript モジュールとする。
理由: 作品ページから実画像 URL を辿る二段階の処理やタグ名前空間の解釈は、セレクタと URL テンプレートだけでは表現できない。

#### ローダー
- プロファイルは純粋な TypeScript（Node / Electron 非依存）とし、main と renderer の両方が読む
  - main: `src/main/external/profileLoader.ts` が実行時に `private/` を `require` し、無ければ `example/` にフォールバックする。`tsconfig.main.json` の include に `src/shared/sites/**` を加え、存在するときだけコンパイルされる
  - renderer: `webpack.config.js` がビルド時に `private/index.ts` の有無を見て `@site-profile` エイリアスの先を決める。`tsconfig.json` の `paths` は両方を列挙し、型検査も同じ順でフォールバックする
- これにより CI や他環境でもビルド・テストが通る
- `build:main` は先に `dist/` を消す。消さないと `private/` を削除した後も `dist/shared/sites/private` が残り、main が古いプロファイルを読み続ける
- フォールバック時は UI 上に「サンプルプロファイルで動作中」と表示する（IPC `external-get-profile-info` で判定）

#### SiteProfile インターフェース（概略）
```typescript
interface SiteProfile {
  id: string;
  displayName: string;
  allowedHosts: string[];
  rateLimit: { minIntervalMs: number; maxConcurrency: number };
  buildListUrl(query: ListQuery): string;
  parseListPage(doc: Document): { works: ExternalWork[]; nextCursor: string | null };
  parseWorkPage(doc: Document): { pageUrls: string[]; tags: Tag[] };
  parseImagePage(doc: Document): { imageUrl: string };
}
```
`ListQuery` のカテゴリ・言語の値はプロファイルが定義する定数を参照し、公開側はそれを不透明な値として扱う。

### 2. 流出防止

- `.gitignore` に `src/shared/sites/private/`、`tests/fixtures/private/`、`.private-terms` を追加する
- ローカル専用の git hook（pre-commit と commit-msg）で、gitignore 済みの語句リスト（`.private-terms`）に一致する文字列がステージ内容・ファイル名・コミットメッセージに含まれていたら commit を拒否する。hook の雛形は `scripts/git-hooks/` にコミットし、`npm run hooks:install` で `.git/hooks/` に配置する
- 実サイトの HTML を使うテストは `tests/fixtures/private/` に置き、コミットするテストはサンプルプロファイルと合成 HTML だけで動かす
- 公開側コードの命名はサイトの語彙を避け、中立語に統一する
- プロファイルのバックアップは手動で行う（別リポジトリは作らない）

### 3. マルウェア対策

最大の防御は「サイトの HTML をブラウザとして描画しない」こと。HTML はテキストとして取得し、構造化データだけを抜き出す。これにより広告スクリプト、トラッカー、悪性リダイレクトは一切実行されない。

#### HTML の取得とパース
- 取得は main プロセスの Node `https` で行う（Chromium の session を使わないため、ディスクキャッシュに残らない）
- 既存の `fetch-url` ハンドラを拡張し、プロファイルの `allowedHosts` 以外のホストを拒否する
- リダイレクト先も同じ検査を通す。localhost と私有アドレス帯は拒否する
- パースは renderer の `DOMParser` を使う。`parseFromString` が返す Document は inert で、スクリプト実行や画像ロードは起きない
- パース結果は型付きのプレーンオブジェクトとしてのみ扱い、取得した HTML を live DOM に挿入しない

#### 画像の取得と検証
- 画像は main プロセスで取得し、以下を検証する
  - Content-Type だけでなく先頭バイトのマジックナンバーで JPEG / PNG / GIF / WebP を判定する
  - SVG は外部由来を拒否する（スクリプトを含められるため）
  - サイズ上限を設ける
- renderer への受け渡しは `protocol.handle` で登録した独自スキーム（例: `gallery-image://`）で行う
  - data URL 方式は IPC とメモリを圧迫するため採用しない
  - ハンドラ内で取得・検証したバイト列を返す
- CSP の `img-src` には外部ホストを一切追加しない（独自スキームを追加するのみ）
- サムネイルと閲覧中画像のキャッシュはメモリ内 LRU のみとし、ディスクには書かない

#### renderer のハードニング
- `BrowserWindow` の `webPreferences` に `sandbox: true` を追加する
- 既存の `contextIsolation: true`、`nodeIntegration: false`、`setWindowOpenHandler` による deny、`will-navigate` の抑止は維持する

#### 依存の方針
- HTML パースは DOMParser、HTTP は Node 組み込みで足りるため、新規の実行時依存を追加しない

### 4. データモデル

#### ExternalWork
```typescript
interface Tag {
  namespace: 'artist' | 'language' | 'other';  // プロファイルがサイトの語彙をこの 3 種に正規化する
  name: string;
}

interface ExternalWork {
  id: string;                  // サイト側の識別子（プロファイルが生成）
  url: string;
  title: string;
  categoryId: string;          // プロファイル定義の値
  tags: Tag[];                 // artist 名は artistNamesOf(tags) で取り出す
  thumbnailUrl: string | null;
  pageCount: number | null;    // 一覧に無ければ作品ページ取得後に埋める
  fetchedAt: string;           // ISO 8601
}
```

#### Preferences
```typescript
interface ExternalPreferences {
  schemaVersion: 1;
  favoriteWorkIds: string[];
  favoriteArtists: string[];
  ignoredWorkIds: string[];
  ignoredArtists: string[];
}
```

#### 永続化
- userData 配下の `external-preferences.json` に保存する
- 一覧のキャッシュは保存しない（起動ごとに取得する）
- SQLite への移行は、一覧キャッシュを保持する必要が出た時点で検討する

### 5. 一覧機能

#### 取得
- サイト側のクエリで絞り込める条件（表示カテゴリ、言語）はプロファイルの `buildListUrl` が URL に反映する
- NG 除外とお気に入り絞り込みはクライアント側で行う
- artist タグが一覧ページに載る表示モードをプロファイルが要求し、作品ごとの追加取得（N+1）を避ける

#### 表示ルール
1. NG 作品、および NG artist を含む作品は表示しない
2. 「お気に入りのみ表示」フィルタ ON のとき、お気に入り作品、およびお気に入り artist を含む作品を表示する
3. **NG はお気に入りより優先する**。作品がお気に入りでも artist が NG なら表示しない

#### ページネーション
- プロファイルが返す `nextCursor` を不透明な値として扱い、「次へ」で続きを取得する

### 6. 閲覧機能

- 作品ページ → 各ページの HTML → 実画像 URL の二段階取得となる
- 先読みは次 2 ページまで
- 同時接続数と最小リクエスト間隔はプロファイルの `rateLimit` に従う（既定: 同時 1、間隔 1000ms）
- 短時間の大量アクセスはサイト側で制限されるため、レート制御は必須機能として扱う
- 既存のダウンロードパイプライン（`processDownloadJob`）とは目的が異なるため、別モジュール `src/main/external/` として実装する
- 取得失敗時はそのページをスキップ可能にし、エラー内容をログパネルに出す

### 7. お気に入り / NG 機能

- 一覧カードと閲覧画面の両方から、作品単位と artist 単位で操作できる
- artist 単位の操作は、作品の `artistTags` を列挙して選択させる
- 設定パネルに一覧表示と解除の UI を置く

### 8. UI

- SideMenu に中立な名称のパネル（`ExternalPanel`）を追加する
- 一覧には既存の `ImageGrid` を、閲覧には `ImagePreview` を再利用する
- フィルタ: 「お気に入りのみ表示」トグル
- サンプルプロファイルで動作中の場合はバナーで明示する

## 実装ステップ

### Step 1: 基盤
- `SiteProfile` インターフェースと型定義
- サンプルプロファイル `src/main/sites/example/`
- ローダーとフォールバック
- `.gitignore` と pre-commit hook の整備

### Step 2: 取得と検証
- `fetch-url` のホスト許可リスト対応
- 画像取得・検証と `protocol.handle` の登録
- レート制御

### Step 3: 一覧
- 一覧取得と表示ルールの実装
- お気に入り / NG の永続化
- フィルタ UI

### Step 4: 閲覧
- 二段階取得と先読み
- 閲覧画面からのお気に入り / NG 操作

### Step 5: テスト
- 単体: 表示ルール（NG 優先、artist 展開）、画像検証（マジックナンバー、SVG 拒否）、ホスト許可リスト
- E2E: サンプルプロファイル + ローカル画像サーバーで一覧と閲覧の動線を確認
- 実サイトの HTML を使うテストは `tests/fixtures/private/` に置き、ローカルでのみ実行する

## 既存コードへの影響
- `src/main/ipc.ts`: `fetch-url` にホスト検査を追加。既存のダウンロード機能はプロファイル非依存のまま維持する
- `src/main/index.ts`: `sandbox: true` の追加、独自スキームの登録
- `public/index.html`: CSP の `img-src` に独自スキームを追加
- `src/main/preload.ts`: 外部ギャラリー用 API の追加

## 関連する整理（本 ADR と同時に実施）
- `src/renderer/utils/scraper.ts` のコメントと `doc/adr/1-5-1.md` から別サイトのドメインを除去し、`example.com` に統一
- `downloads/` を `.gitignore` に追加

## 検討したが採用しなかった案
- **宣言的 JSON プロファイル**: 二段階取得やタグ解釈を表現できないため不採用
- **`<webview>` でサイトを表示**: サイトのスクリプトが実行されるため、マルウェア対策の前提に反する
- **data URL での画像受け渡し**: base64 化による IPC とメモリの圧迫が大きいため、独自スキームを採用
- **Chromium session での取得**: ディスクキャッシュに画像が残り、「画像を保存しない」前提が崩れるため不採用
- **プロファイル用の別リポジトリ**: 手動バックアップで十分と判断
