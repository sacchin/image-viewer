# ネットワークフォルダ検索の高速化 - インデックス実装計画

## 現状分析
- **Electron + React + TypeScript**のアーキテクチャ
- ネットワークフォルダ対応済み（UNCパス、ネットワークドライブ）
- 現在は都度フォルダを読み込む同期的な実装
- electron-storeパッケージが既にインストール済み（永続化に利用可能）

## 実装方針

### 1. インデックスシステムの設計
- **SQLiteデータベース**を使用（better-sqlite3）
- インデックスキャッシュの実装
- バックグラウンドインデクシング
- アプリ終了時の差分更新

### 2. 主要コンポーネント

#### A. データベース層（`src/main/database/`）
- `IndexDatabase.ts` - SQLiteデータベース管理
- `FileIndex.ts` - ファイルインデックス操作
- スキーマ：
  ```sql
  - files (path, name, size, modified, folder_path, created_at, updated_at)
  - folders (path, name, parent_path, last_scan, created_at)
  - index_meta (key, value) - インデックス状態管理
  ```

#### B. インデクサー（`src/main/indexer/`）
- `NetworkIndexer.ts` - ネットワークフォルダスキャン
- `IndexWorker.ts` - バックグラウンドインデクシング
- `IndexCache.ts` - メモリキャッシュ層

#### C. IPC拡張（`src/main/ipc.ts`）
- `index-folder` - フォルダのインデックス作成
- `search-indexed-files` - インデックスからの高速検索
- `get-index-status` - インデックス状態の取得
- `rebuild-index` - インデックスの再構築

### 3. 最適化技術

#### A. パフォーマンス最適化
- **バッチ処理**: 1000ファイル単位でDB挿入
- **並列スキャン**: worker_threadsで並列処理
- **メモリキャッシュ**: LRUキャッシュ（最大1000エントリ）
- **遅延インデックス**: 初回表示を優先、バックグラウンドでインデックス

#### B. ネットワーク最適化
- **接続プーリング**: ネットワーク接続の再利用
- **タイムアウト設定**: 応答なしフォルダのスキップ
- **再試行ロジック**: 一時的なネットワークエラー対応

#### C. 差分更新（アプリ終了時）
- **終了時の自動更新**: `app.on('before-quit')` でインデックス差分更新
- **変更検出**: ファイルのタイムスタンプと比較
- **高速スキャン**: 変更があったフォルダのみ再スキャン
- **グレースフルシャットダウン**: 更新完了までアプリ終了を待機

### 4. 実装手順

1. **依存パッケージのインストール**
   - better-sqlite3
   - chokidar（ファイル監視）
   - p-queue（並列処理制御）

2. **データベース層の実装**
   - スキーマ定義とマイグレーション
   - 基本的なCRUD操作

3. **インデクサーの実装**
   - フォルダスキャン機能
   - バックグラウンドワーカー
   - キャッシュ層

4. **IPC通信の拡張**
   - 新しいハンドラーの追加
   - 既存機能との統合

5. **アプリ終了時の差分更新実装**
   - 終了イベントのハンドリング
   - 差分検出と更新処理
   - 進捗状態の保存

6. **テストとデバッグ**
   - ユニットテスト作成
   - エラーハンドリング
   - ログ出力の実装

## 期待される効果
- **初回読み込み**: 10-20倍高速化（キャッシュ済みの場合）
- **検索速度**: ミリ秒単位での応答
- **メモリ使用量**: 最適化により最小限に抑制
- **ネットワーク負荷**: キャッシュにより大幅削減
- **終了時の更新**: 次回起動時に最新状態を保証
